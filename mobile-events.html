1任务一 · 事件侦探

在下面这块区域里用手指按下、拖动、抬起。日志按真实顺序记录四个触摸事件与 click，并统计 touchmove 次数。

用手指在这里按下并拖动
touchstart 0 touchmove 0 touchend 0 click 0
等待你的第一次触摸……
操作观测到的事件顺序（设备模式实测）
单击touchstart → touchend → click（没有 touchmove）
向上拖动touchstart → 连续 touchmove（约 20～40 次）→ touchend → click
向左快速滑touchstart → 少量 touchmove（约 5～10 次）→ touchend → click
双指触摸touchstart（touches.length = 2）→ 每个手指各自产生 touchmove → touchend 依次触发
长按后抬起touchstart →（600ms 内无 touchmove）→ touchend → click

数值说明：touchmove 的次数取决于手指移动距离、移动速度和设备采样率，实测同一次操作每次也会有差别，所以记录用"区间"而不是精确值。

三个思考问题
  • ① 一次拖动里 touchmove 大约触发多少次？和距离有什么关系？ 一次正常拖动大约触发 20～40 次；距离越长、移动越慢，触发次数越多。因为浏览器在手指位置发生变化时就会派发一次 touchmove，采样周期约 8～16ms，所以次数 ≈ 拖动时长 ÷ 采样周期；快速甩动只有 5～10 次，慢速拖动可超过 50 次。
  • ② click 出现在 touchend 之前还是之后？ 之后。touchend 先触发，浏览器再确认"这不是双击、也没有被阻止"，才补发一次 click。如果两套逻辑都写，一次点击会执行两次，需要在 touch 处理里 preventDefault() 或二选一。
  • ③ 如果把 touchend 换成 touchcancel，会发生什么？ touchcancel 只在"手势被系统打断"时触发（来电、通知下拉、系统手势返回、浏览器接管滚动），正常抬手根本不会触发。换成它之后，用户正常滑动抬起时收不到任何回调，翻页/拖动逻辑就会失效；正确做法是两者都监听，touchcancel 里只做"清理状态、回弹"，不做业务动作。

3踩过的坑与解决办法
  • 双指缩放时图片"跳走"：一开始每帧都用 scale *= 本帧比例 累乘，误差越滚越大，且锚点固定在左上角。改成"以手势开始时的距离与倍数为基准算相对比例"，并用两指中点补偿位移，跳动消失。
  • 横向滑动时整页跟着上下抖：卡片容器最初只有 touch-action: pan-y 却忘了在 touchmove 里判断方向，纵向拖动也被当成横向。改为先比较 dx 与 dy，只有横向更大才接管。
  • 快速连滑一次跳两张：touchend 很短时间连续触发两次判断。加 300ms 冷却锁后解决。
  • 手机上摇一摇没反应：页面不是 HTTPS 或 iOS 未授权时收不到 devicemotion。加了 1.2s 超时检测 + 授权按钮 + "点我抽一次"降级。
  • 拖动结束后卡片卡在半张：没有监听 touchcancel，来电回来状态没清理。补上后统一回弹到当前页。
